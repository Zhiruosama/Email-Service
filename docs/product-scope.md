# 产品边界与设计原则

## 1. 产品定位

Mail Service 是邮件投递基础设施，不是某个业务的验证码子模块，也不是第一阶段就
建设完整的营销自动化平台。

它向多个可信业务系统提供统一能力：

- 幂等受理单封或批量邮件命令；
- 立即发送、定时发送和截止时间控制；
- 版本化模板、国际化和变量校验；
- 多供应商路由、故障转移和流量隔离；
- 异步投递、退避重试、熔断、死信和人工重放；
- 投递状态查询和可靠事件通知；
- 租户配额、审计、指标、日志和链路追踪。

AI-Nexus 的验证码邮件是第一个业务场景。验证码本身的生成、摘要存储、激活、验证
和消费继续由 AI-Nexus 负责。

## 2. V1 范围

V1 支持：

- 一个逻辑消息对应一个收件人；
- 事务类邮件；
- 已注册模板发送；
- 立即发送和未来时间发送；
- SMTP Provider；
- Fake Provider；
- gRPC 提交、查询和取消接口；
- gRPC 状态订阅适配器；
- PostgreSQL 权威任务状态；
- RabbitMQ 异步传输；
- 至少一次处理和业务幂等；
- 多租户认证、限流和配额；
- Outbox、重试、熔断和 DLQ；
- Prometheus/OTLP 可观测数据。

批量接口可以一次接收多个收件人，但服务端必须拆成独立消息。不得把多个互不相关的
收件人放入同一 SMTP Envelope，以免状态、重试、退信和隐私相互耦合。

## 3. 非目标

V1 不包含：

- 用户旅程和营销活动编排；
- 邮件联系人管理和受众分群；
- 所见即所得模板编辑器；
- IMAP 收件箱；
- 任意动态 HTML 发送；
- 动态 callback URL；
- 对“最终进入收件箱”的虚假承诺；
- 跨数据库、RabbitMQ 和供应商的分布式事务；
- 严格 Exactly Once 投递承诺。

## 4. 核心原则

### 4.1 受理不等于送达

同步 API 只承诺任务已经可靠写入数据库。SMTP 或供应商接受、最终送达、退信属于
后续异步状态。

### 4.2 数据库是权威状态，消息队列是传输通道

任务、调度时间、尝试次数和终态保存在 PostgreSQL。RabbitMQ 用于解耦和削峰，
不是长期任务的唯一存储，也不是日历调度器。

### 4.3 至少一次 + 幂等

系统允许消息重复出现，但每个阶段都必须能安全处理重复。任何网络超时都不能被解释
为“对方一定没有执行”。

### 4.4 控制面与数据面分离

控制面管理租户、模板、发件身份、供应商凭据、路由和配额。数据面只执行已发布的
配置和投递任务。控制面故障不应立即阻断已有邮件投递。

### 4.5 通用核心不感知业务

核心认识“租户、模板、消息、供应商和投递事件”，不认识注册、订单或验证码验证
规则。业务语义通过模板变量 Schema 和调用方适配器表达。

### 4.6 安全默认值

默认只允许已注册模板、已验证发件身份和预注册事件目标。敏感变量加密保存，日志、
错误和 Trace 中禁止出现正文、完整邮箱和验证码。

## 5. 服务等级分类

邮件类别用于资源隔离和策略选择：

| 类别 | 示例 | 优先级 | 默认截止时间 | 默认重试策略 |
| --- | --- | ---: | --- | --- |
| `CRITICAL` | 登录/重置验证码 | 最高 | 2 分钟 | 短退避、快速失败 |
| `TRANSACTIONAL` | 订单、支付、账户通知 | 高 | 30 分钟 | 有界指数退避 |
| `NOTIFICATION` | 普通产品通知 | 中 | 24 小时 | 较长退避 |
| `BULK` | 批量运营邮件 | 低 | 可配置 | 严格限速 |

V1 首先交付 `CRITICAL` 和 `TRANSACTIONAL`。类别决定队列、Worker 并发、超时和
降级策略，防止批量任务挤占验证码邮件。

## 6. 通用 API 边界

通用提交协议应使用中立命名，例如 `mailservice.delivery.v1`，而不是
`ainexus.mail.v1`。

提交命令的核心字段：

- `idempotency_key`：调用方生成，租户内唯一；
- `recipient`：单个收件人；
- `sender_identity`：预注册发件身份；
- `template_key`：稳定模板键；
- `template_version`：可选；为空时在受理时解析并固定活动版本；
- `locale`；
- `variables`：受模板 JSON Schema 校验；
- `category` 和 `priority`；
- `scheduled_at`；
- `dispatch_deadline`；
- `metadata`：受大小和键名限制，不得放敏感信息。

租户身份必须来自 mTLS 身份或访问令牌，不能仅信任请求体中的 `tenant_id`。

AI-Nexus 可以通过专用适配器把强类型 `VerificationCodePayload` 转换为通用模板
变量。适配器保留现有业务友好的协议，核心领域模型不依赖 AI-Nexus。
