# ADR-0001：采用可按角色部署的模块化单体

- 状态：Proposed
- 日期：2026-07-28

## 决策

使用一个 Go 仓库和一个二进制，通过 `--role` 分别运行 API、Scheduler、Relay、
Worker、Event Ingress、Notifier 和 Reconciler。

## 原因

- 领域边界尚在形成阶段；
- 单仓库便于保证状态机、错误类型和协议一致；
- 不同角色仍可独立扩容和隔离；
- 将来可以沿现有模块边界拆分，无需现在承担分布式开发成本。

## 后果

- 模块之间必须通过明确接口交互；
- 禁止跨模块直接修改其他模块的数据表；
- 启动和配置系统需要支持角色化依赖检查；
- 单个发布物变更仍可能影响多个角色，需要完整回归。
